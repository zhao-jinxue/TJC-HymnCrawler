# PPT + PDF + PNG 三源综合方案可行性调研

- 日期：2026-09-15
- 工具链：Cline
- 涉及模块：`crawler_core/pdf_jianpu.py`（既有 POC）、`Hymn_Downloads/`（官方 PDF/PNG）、`data/赞美诗PPT/`（PPT 源）、`tool/qwen_ocr.py`（视觉模型通道）

## 背景

上一次会话（`docs/sessions/2026-09-13_19-18-00.md`）已完成「PPT 记谱 × 官方简谱 PDF」逐字几何对位 POC，并明确其硬边界是**粒度不可比**（PPT 合成字形 1 字符/拍 vs PDF 把减时线/附点拆成独立字符）。

本次用户提问：**PPT + PDF + PNG 三源综合（PDF 为主、PPT 为辅、难抉择时用图片识别）这个套路是否可行？**

回答该问题必须先确定三件事实，本任务即围绕取证展开（**只读探查 + 视觉 API 实测，未改动业务代码**）。

## 任务 1：三源是否互相独立 + 图片识别通道能否胜任裁决

### 提问

> 那么 PPT + PDF + PNG 三个元素综合呢，以 PDF 为主，PPT 为辅，难以抉择的使用图片识别，这个套路是否可行？

### 解决思路

把「三源综合」拆成三个必须单独证伪的问题，逐个做实测而不是凭直觉判断：

1. **PNG 是不是独立第三源？** 若 PNG 只是 PDF 的位图版，则「三源」实为「两源 + 一个渲染通道」，架构上不该按三个源来设计。
   判据：把官方 PDF 用 pymupdf 渲染成图，与官方 PNG 对齐后比内容区比例、墨迹占比、像素相关系数。
2. **「图片识别」通道的必要规模？** 若绝大多数 PDF 自带文本层，则 OCR 只是例外通道，而非常规路径。
   判据：统计 474 首官方简谱 PDF 的文本层字符数分布与页面内嵌图片数。
3. **视觉模型能否胜任「难抉择时的裁决」？** 要看它在**本项目真正需要的能力**（读八度点、逐字对位）上的表现，且要分清「模型不会读」与「输入方式不对」。
   判据：用同一张官方简谱图做三组对比实验——整块输入、单行裁图输入、单行裁图 + 明确简谱规则提示。

### 最终结果

#### 事实 1：PNG 不是独立源，它是 PDF 的位图孪生（三源 → 实为两源）

`Hymn_Downloads/<编号_标题>/` 下每首 4 个文件：`*_简谱.pdf` / `*_简谱.png` / `*_五线谱.pdf` / `*_五线谱.png`（474 首 × 2 版式 = 948 PDF / 948 PNG）。

对 #1 的比对（脚本 `/tmp/probe_pdf.py`）：

| 指标 | 官方 PNG | 官方 PDF @240dpi 渲染 |
| --- | --- | --- |
| 页面/图幅比例 | 0.6559（1984×3025） | 0.7070（A4 595×842pt）→ 渲染 1985×2807 |
| **裁白边后内容区比例** | **0.6466**（1905×2946） | **0.6463**（1524×2358） |
| 墨迹占比（<128 灰阶） | **0.0556** | **0.0556** |
| 内容区对齐后相关系数 | — | 0.8457（上部 1/3 为 0.8117，差异仅来自抗锯齿） |

并排目视（`/tmp/cmp_top.png`）：左 PNG / 右 PDF 渲染**逐像素同排版**，标题、调号、四声部、歌词完全一致。

→ 官方 PNG = 官方 PDF 去掉 A4 白边的高清位图。**用 PNG 与用 PDF 渲染得到的是同一信息**，不构成独立第三源。

#### 事实 2：474 首简谱 PDF 全部带文本层，「图片识别」只是例外通道

统计结果（脚本 `/tmp/probe_pdf_text.py`）：

```
简谱 PDF 总数: 474
文本层分布: {'无文本(<10)': 0, '极少(10-200)': 0, '中等(200-2000)': 401, '丰富(>2000)': 73}
页面内嵌图片对象累计: 14331   （≈30 个/页）
```

→ 没有一首是「整页图片版」。#349 的问题不是缺文本层，而是其它结构差异（需另行排查）。
→ 页面内嵌的 14331 个图片对象印证了既有结论：**小节线、延音弧等装饰是图片，不在文本层**，这才是几何对位需要图形判据的原因。

#### 事实 3：视觉模型「读单行可靠、对位不可靠」，且模型选择有硬差异

三组实验（同一首 #1 官方简谱 PNG，Qwen-VL，`temperature=0.1`）：

| 实验 | 输入 | 模型 | 结果 |
| --- | --- | --- | --- |
| A | 整块（含双声部 + 3 段歌词，1905×900 原分辨率） | `qwen-vl-max` | 8 小节音符数字**读对**；但**低八度点系统性丢失**（`6̣`→`6`、`4̣`→`4`），**逐字对位大面积 `?` 且错位**（把下一乐段歌词算进本节） |
| A | 同上 | `qwen-vl-ocr` | 输出 JSON 但文字块切分错乱（漏字），音符仅按空白切分，**无用** |
| B | **单行裁图**（低音声部一行，2× 放大） | `qwen-vl-max` | `1 1 6. 6. \| 5. - 1 - \| 4. - 4 4 \| 1 -` — **与目视真值逐字一致，八度点全对** |
| B | 同上 | `qwen-vl-ocr` | `11665-1-4-441-` — 丢失小节线与间隔，**无用** |

（实验 A 中同图残留的半个上行被读错，属输入残缺，不计入模型能力评价。）

→ 结论：**`qwen-vl-max` 是「逐行读数器」而不是「对位器」；`qwen-vl-ocr` 完全不适用于简谱。**
→ 扬长避短的用法：**由程序按行切片（PDF 文本层的行 bbox 天然给出切片范围）→ 模型只读单行 → 仍由程序做逐字对位**。这是可行且低成本的例外通道。

### 综合结论（回答用户提问）

| 原方案设定 | 取证结论 | 修订建议 |
| --- | --- | --- |
| PDF 为主 | ✅ 成立，且 PDF 同时提供「文本层 + 可渲染像素」两条通道 | 保持主线：`pdf_jianpu` 几何对位 |
| PPT 为辅 | ✅ 成立，但粒度不可比，宜作**候选真值/投票源**而非对位源 | 先做拍位聚合/粒度归一，再用于交叉校验 |
| PNG 作第三源 | ❌ 不成立：PNG 是 PDF 的位图孪生，无新信息 | 不算第三源；需要像素时现场渲染 PDF 即可 |
| 难抉择时用图片识别 | ⚠️ 部分可行：仅作**逐行读数裁决**（qwen-vl-max），**不能**做对位裁决 | 例外通道：按行切片 → 单行读数 → 程序对位；只用于几何对位失败的争议行 |
| （原方案遗漏） | — | 若要真正的独立第三源，应是**五线谱**（另一记谱体系，474 首齐备），但需五线谱识谱，成本另计 |

### 遗留问题

1. 事实 2 显示 #349 **并非**无文本层 → 上次会话把它归为「疑似图片版」的判断需要修正，应重新排查其真实失败原因。
2. 「拍位聚合/粒度归一」仍未实现，是全量命中最关键的一步。
3. 视觉裁决通道若要落地，需新增按行切片工具（`tool/show_pdf_align.py` 已有行 bbox 与渲染能力，可复用）与单行读数结果与 PPT 行的序列比对逻辑。
4. 真正的第三独立源（五线谱）可行性未评估。

## 会话总结

- 本次共处理 1 个任务（三源综合方案可行性取证），**未改动业务代码**，仅新增本会话日志。
- 关键收获：
  1. 「多源」必须先用**量化判据**验证源的独立性——本项目里 PNG 与 PDF 内容区比例 0.6466 vs 0.6463、墨迹占比完全相同，实为同一信息的两种编码；
  2. 视觉模型的能力边界要按**任务动作**切分验证：`qwen-vl-max` 读单行简谱（含八度点）完全正确，但整块对位与八度判定崩坏；`qwen-vl-ocr` 对乐谱语法完全不可用；
  3. 474/474 首 PDF 均有文本层 → 图片识别应定位为**例外裁决通道**，而非常规流水线环节。
- 遗留事项：拍位聚合（提升命中率）→ 视觉裁决通道落地 → 五线谱源评估 → 全量表结构设计，四项均待用户决定是否启动。
